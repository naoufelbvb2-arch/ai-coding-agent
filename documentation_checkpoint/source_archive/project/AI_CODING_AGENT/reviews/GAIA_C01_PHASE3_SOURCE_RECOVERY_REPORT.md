## Exact source admission procedure

1. **Receive immutable source.** Import RDMS-XX final, frozen full document or a complete approved export. Do not promote summaries, screenshots, draft snippets, or guessed types.
2. **Establish provenance.** Record filename, revision, approval/freeze status, original location and associated correction chain; verify or compute content SHA-256. A hash verifies identity of captured bytes, not approval status by itself.
3. **Identify supersession.** Distinguish draft, C01/C02 corrections, and final consolidated legal text; record explicit precedence and do not silently select the newest filename.
4. **Extract each normative unit.** Index owned types, fields, enum values, state transitions, authority guards, persistence requirements, error semantics, invariants and test gates.
5. **Map by owner.** Add the exact text or an explicitly validated lossless equivalent only to its owning L0–L7 layer; other layers receive references/projections, not second legal definitions.
6. **Check conflicts.** Compare against FCA and already admitted RDMS owners, especially Action/Control, Trigger/Recovery, Specialist/Dependency, Memory/Data and Provider/Transport.
7. **Adversarial review.** Record differences with concrete examples and a freeze decision. A conflict with a frozen parent requires formal change control, never automatic overwrite.
8. **Admit and publish.** Mark source verified, update the source registry, generate the exact law/type migration map, and only then propose a consolidated layer freeze.
